## Requirements

- Python 3.9 or higher
- No OPA binary — evaluation is in-process via `regopy`

## Core package

```bash
pip install comply54
```

This installs the evaluation engine, all 21 policy packs, and the sector packs for Nigeria (fintech, healthcare, insurance), Kenya, and Pan-African coverage.

## Environment variables

comply54 requires no mandatory environment variables. Optional configuration:

| Variable | Default | Description |
|----------|---------|-------------|
| `COMPLY54_AUDIT_BACKEND` | `none` | Audit log destination: `none`, `stdout`, `file`, or a URL |
| `COMPLY54_AUDIT_FILE` | `comply54-audit.jsonl` | Path when `AUDIT_BACKEND=file` |
| `COMPLY54_STRICT_MODE` | `false` | Treat `escalate` decisions as `deny` |

## Docker / Lambda

comply54 works in any Python environment — no system dependencies:

```dockerfile
FROM python:3.12-slim
RUN pip install comply54
```

The `regopy` wheel bundles Microsoft's rego-cpp, a C++ implementation of Rego, as a compiled extension. No `apt-get` or `brew install opa` is required.

### Engine compatibility

rego-cpp is a separate implementation from OPA, and it handles some text differently. comply54 compensates so the bundled packs behave as they do under OPA, and a CI job checks every output regex against real OPA:

- **Case-insensitive matching.** Packs match lowercase patterns against lowercased text instead of using `(?i)`, which rego-cpp does not support.
- **Line breaks and control characters.** Tabs, line breaks, form feeds and carriage returns in evaluation input are treated as spaces, and other control characters as a non-space placeholder. A pattern's `.` can therefore match across what was a line break, which can only add matches, never remove them.
- **Non-ASCII text.** rego-cpp's regex engine counts bytes, not characters. Before evaluation, non-ASCII characters in the agent output are replaced with a one-byte placeholder, except characters that a loaded pack or your config mentions (such as `₦` or Arabic text), which stay matchable. Signed receipts still hash the original output.
- **Quotes and backslashes** are passed through with an escape that rego-cpp keeps, so only length checks (`count`) see one extra character for each.
